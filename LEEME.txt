SUSU LATAM v26 — Badge de huella digital que se actualiza solo
==============================================================

EL PROBLEMA QUE RESUELVE
1) El widget original decía "No Result" en las subpáginas porque consultaba
   la API por la URL exacta de cada página, y solo la portada había sido
   testeada.
2) Un badge con la fecha escrita a mano quedaba viejo al mes siguiente.

CÓMO FUNCIONA AHORA
- El HTML trae el dato verificado escrito, así que el badge SIEMPRE se ve,
  aunque la API no responda. Nunca más un "No Result".
- Un script chiquito (assets/carbon.js) consulta la API preguntando por
  susulatam.com — el dominio, no la página actual. Como el dominio sí está
  testeado, la consulta funciona desde cualquier subpágina.
- Si la API responde, actualiza el número y pone la fecha del día. La fecha
  deja de envejecer sola.
- El resultado se guarda una semana en el navegador del visitante, así no se
  consulta la API en cada carga y no se choca contra su límite diario.
- Si la API falla, está caída o devuelve algo raro, no toca nada: queda el
  dato de respaldo. Probé los cinco escenarios posibles.
- Si algún día el sitio se vuelve pesado (más de 0,1 g por visita), el
  script esconde la nota "A+" en vez de mostrar una calificación que ya no
  corresponde.

NOTA SOBRE EL DATO DE RESPALDO
La fecha escrita en el HTML es la del día en que generé estos archivos.
Solo se ve si la API nunca respondió en el navegador del visitante. En la
práctica, casi siempre se va a ver la fecha real de la consulta.
